# Jev 本地决策层调研复核

日期：2026-10-27。范围：源码与公开一手资料核查；未部署、未修改业务代码、未运行模型基准。

## 结论

适合增加本地语义判断，但应先验证已有 Laya 接入是否真正工作，再决定换模型。推荐 Laya multilingual 做第一轮验证，Kev-0.8B 做对照；不能凭通用榜单认定任何一个适合中文衔接词。

## 当前项目的实际状态

- 已存在 `server/src/decide/`，使用 `@receptron/laya` 在独立 worker 内推理，判断四类意图及是否开口。
- `config.ts` 默认关闭决策，只有 `DECIDE_ENABLED=true` 才开启；本次未在 server/.env 检出该项。运行进程是否通过外部环境开启，尚未核实。
- 模型目录只发现 `laya.onnx` 与 `laya.onnx.data.part`，未发现完整数据文件及其余加载资产；当前磁盘副本不足以证明可用。
- 输入只有本轮最后一条消息，没有对话历史；“好”“继续”“不是这个”等依赖上下文的判断信息不足。
- 未就绪、超时或失败会退回随机选词。自定义词没有匹配的内置意图文案时，也会随机选词，因此即使模型工作，仍可能词不达意。
- 意图为 ack / think / greet / wait。ack、think、wait 有明显交叉，模型并不知道主回答实际需要多久，不能仅靠用户问题推断等待时间。
- `speech.ts` 的播报任务等待 filler 完成；衔接词合成开始后，正文到达不会立刻取消该合成。因此“决策并行”不等于“正文音频不受衔接词延迟影响”。

## 本地候选

| 候选 | 已核实的信息 | 本项目定位 |
| --- | --- | --- |
| Laya multilingual | 322M、mmBERT、Apache-2.0、非自回归决策；官方明确提示概率未标定，部分零样本决策任务接近随机 | 优先复用已有接入，但必须验证中文任务效果 |
| Kev-0.8B | Qwen3.5 底座、Apache-2.0，支持 Apple Silicon MLX；作者将小模型定位为体积优先 | 作为独立对照，中文能力与延迟需本机测量 |
| SemIf / OpenJev | 开放模型的语义决策框架，支持 MLX 和 MPS | 已有本地模型时适合复用，模型选型与校准工作更多 |
| local-jev | MIT 的本地服务，兼容 Jev API，默认 Qwen，作者标注研究项目 | 适合需要 Jev API 兼容时使用，当前 Node 项目没有这项硬需求 |

Jev 官方提供 state + typed questions → 结构化判断的云端 API。此次查看的官方资料未提供本地权重部署路径，因此本地方案应表述为同类替代。

## 建议的业务判断

先定义“是否值得先开口”，再选择可接受的回应类别。业务候选可从：问候、收到明确请求、需要解释的问题、承接追问、情绪回应、保持安静开始。这只是待验证的分类草案。

输入应包含本轮文本、少量最近对话，以及必要的交互状态。停止、取消等指令继续由确定性的现有控制链路处理；不要等待衔接词分类。

选词失败默认安静更符合自然交互；自定义文案应绑定类别，或者在没有匹配类别时不播。模型与主回答并行运行，正文可播时应允许放弃尚未就绪的衔接词。

## 验证计划

整理约 100–200 条中文场景，给每条标注“允许哪些开场/是否应安静”，无需强行给近义词唯一标准答案。覆盖问候、技巧问题、连续追问、否定纠正、停止、短确认及情绪表达。

比较随机基线、规则基线、Laya 与 Kev-0.8B。记录不合时宜开口率、上下文冲突率、类别混淆、冷启动耗时、热推理 P50/P95，以及正文首段音频的延迟变化。概率未经过本任务校准前，不设通用置信度门槛。

旧调研中的 M2 40–70ms 是估计，不能作为实测结论；不同硬件、缓存与请求长度的公开速度不可直接横比。
